# 03 多模态工作流

前两章分别讲了图片理解和语音转写。本章把它们组合成真实应用里的工作流。

## 本章要点

- 多模态应用通常不是“直接把图片/音频丢给模型”这么简单。
- 图片、语音、OCR、ASR 的结果往往要转成结构化文本，再交给 LLM。
- 多模态输入要考虑成本、隐私、延迟和可追溯性。
- 生产系统应保存原始文件、识别结果和模型回答之间的关联。

## 运行

本章示例不调用视觉或语音模型，只用模拟 OCR/ASR/视觉结果演示工作流结构：

```bash
uv run tutorials/18_multimodal/03_multimodal_workflows/main.py
```

## 常见工作流

### 工单截图理解

```text
用户上传报错截图
  ↓
视觉模型识别错误信息、按钮、页面状态
  ↓
LLM 结合知识库生成排查步骤
  ↓
客服确认后回复用户
```

输出结构示例：

```json
{
  "image_type": "error_screenshot",
  "detected_text": ["Network timeout", "Retry"],
  "possible_issue": "网络请求超时",
  "next_steps": ["检查网络", "查看服务状态", "重试上传"]
}
```

### 发票/表单 OCR

```text
上传发票图片/PDF
  ↓
OCR 提取文本和字段
  ↓
LLM 结构化校验
  ↓
写入业务系统或等待人工确认
```

字段示例：

```json
{
  "invoice_no": "INV-2026-001",
  "amount": 299.00,
  "date": "2026-08-09",
  "seller": "云雀科技"
}
```

注意：金额、日期、税号等高风险字段必须允许人工复核。

### 会议录音总结

```text
录音
  ↓
ASR 转写
  ↓
说话人分离（可选）
  ↓
LLM 总结
  ↓
待办提取
```

输出结构：

```json
{
  "summary": "本次会议讨论了知识库上线计划。",
  "decisions": ["下周先灰度给客服团队"],
  "action_items": [
    {"owner": "小王", "task": "整理 FAQ 文档", "due": "周三"}
  ]
}
```

## 设计原则

### 先转文本，再做业务推理

图片和音频通常先变成文本或结构化字段：

```text
图片/音频 → OCR/ASR/视觉理解 → 结构化文本 → LLM 业务处理
```

这样更容易测试、缓存和人工复核。

### 保存中间结果

建议保存：

- 原始文件路径
- OCR/ASR 输出
- 视觉模型描述
- LLM 输入
- LLM 输出
- 人工修正结果

否则用户说“识别错了”时，很难定位是 OCR 错、ASR 错，还是 LLM 总结错。

### 区分低风险和高风险场景

低风险：

- 图片描述
- 会议摘要
- 截图初步排查

高风险：

- 发票金额
- 合同条款
- 医疗影像
- 身份证件

高风险场景必须有人审、字段校验和审计记录。

## 与 RAG 结合

多模态输入常常只是问题入口，真正答案还需要知识库：

```text
用户上传报错截图
  ↓
视觉模型识别错误码 E1024
  ↓
RAG 检索 E1024 排查文档
  ↓
LLM 生成带引用答案
```

## 常见错误

- 只保存最终答案，不保存 OCR/ASR 中间结果。
- 把高风险字段完全交给模型判断。
- 不压缩图片，导致成本和延迟过高。
- 会议转写不分段，LLM 总结时遗漏重点。
- 图片里有敏感信息，却直接发到外部模型。

## 练习

设计一个“客服截图问答”流程，写出：

1. 用户上传什么。
2. 视觉模型输出什么结构。
3. 如何用 RAG 检索知识库。
4. 最终回答如何展示引用。
5. 哪些信息需要脱敏。
