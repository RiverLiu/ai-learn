# 03 手写向量数据库，构建知识库索引

向量数据库听起来神秘，核心其实只有两件事：**存**（向量 + 原文 + 元数据）和
**取**（找与查询向量最相似的 Top-K）。本章用 numpy 实现一个 50 行的最小版本，
把第 2 章切好的知识库块构建成可持久化的索引。

## 本章要点

- `VectorStore.add()`：写入时预先对向量**归一化**，之后检索只需一次矩阵乘法。
- `VectorStore.search()`：`vectors @ query` 一次性算出所有块的余弦相似度，`argsort` 取 Top-K。
- `save()` / `load()`：向量用 `.npz`、文本元数据用 `.json` 分开持久化——索引只需构建一次，之后每次启动直接加载。
- `build_index()`：完整的离线流水线——加载文档 → 切块 → 批量向量化 → 入库。

## 运行

需要 `OPENAI_API_KEY`：

```bash
uv run tutorials/rag/03_vector_store/main.py
```

预期输出：切出 16 个块，保存 `rag_index.npz` / `rag_index.json`，
并对"退款政策是什么"做一次检索，命中最上面的应是 pricing.md 的退款小节。

## 核心概念

- **这就是向量数据库的本质**。生产级产品（Chroma、Qdrant、pgvector、Milvus）额外提供的是：
  十亿级向量的近似最近邻索引（HNSW 等）、按元数据过滤、分布式与增量更新——接口形态与本章一致。
- **暴力扫描的边界**：本章是 O(N) 全量扫描，几千到几万块完全够用；块数到百万级以上才需要 ANN 索引。
- **索引与查询必须走同一条流水线**：切块策略、Embedding 模型任何一边变了，索引都要重建。
