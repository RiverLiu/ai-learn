# 05 Reflection：执行后自我检查与修订

Reflection 指 Agent 在完成一次生成或工具执行后，主动检查结果，找出缺陷，再修订输出。

典型流程：

```text
Draft -> Critique -> Revise -> Final
```

它解决的问题不是“怎么规划步骤”，而是“做完以后怎么发现自己哪里没做好”。

## 本章要点

- **Draft**：先生成一个可检查的初稿。
- **Critique**：按标准检查初稿，例如事实、完整性、引用、格式。
- **Revise**：根据检查结果修订。
- **Stop rule**：达到质量标准或最大反思次数后停止。

## 运行

本章是离线示例，不调用模型 API：

```bash
uv run tutorials/21_planning/05_reflection/main.py
```

## 核心概念

Reflection 常用于这些场景：

- 答案需要覆盖多个要点，容易漏项。
- 生成内容需要符合固定格式。
- RAG 答案需要检查是否引用来源。
- 工具执行结果需要判断是否满足用户目标。

它可以和 Planning 组合：

```text
Plan -> Execute -> Reflect -> Replan or Final
```

如果反思发现“证据不足”，可以回到 ReAct 或 Replanning 继续查；如果只是表达不完整，可以直接修订答案。

## 示例

用户问：

```text
专业版多少钱？支持多少协作者？
```

初稿：

```text
专业版每月 29 元。
```

反思：

```text
缺少“支持多少协作者”的回答。
```

修订：

```text
专业版每月 29 元，支持最多 10 个协作者共同编辑笔记。
```

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 反思只说“挺好” | 没有检查标准 | 明确列出必须检查的维度 |
| 无限反思 | 没有停止条件 | 设置最大反思次数 |
| 修订引入新事实 | critique 阶段没有约束证据 | revise 只能使用已有证据 |
| 只改文风不改事实 | critique 太泛 | 检查事实覆盖、引用、约束条件 |
