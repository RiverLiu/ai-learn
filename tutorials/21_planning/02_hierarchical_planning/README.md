# 02 分层规划：分而治之

当任务大到一次 prompt 装不下、或需要覆盖多个维度时，先把任务**横向拆成子任务**，再逐个击破，最后合并，是更稳妥的做法。

## 本章要点

- **分层规划 = 任务分解 + 分派执行 + 结果合并**。
- **子任务由模型生成**：通过结构化输出得到 `SubTask` 列表，每个子任务带标题和内容要求。
- **worker 复用**：同一个 worker 函数，带着不同子任务的提示词多次调用，生成各小节。
- **合并节点**：按子任务顺序拼接内容，并让模型写一段 executive summary。
- **可扩展**：子任务之间没有强依赖时，可用 LangGraph `Send` 并行分发到多个 worker。

## 运行

```bash
uv run tutorials/21_planning/02_hierarchical_planning/main.py
```

输出会打印：

1. 模型拆分出的 3-5 个子任务。
2. 每个 worker 生成的小节正文。
3. 合并后的完整报告（含摘要）。

## 核心概念

- **planner / worker / compiler 三段式**：
  - `decompose` 负责“拆”；
  - `worker` 负责“做”；
  - `compile` 负责“合”。
- **状态 `sections: dict[str, str]`**：用子任务标题作为 key，把生成的片段暂存，便于最后合并。
- **并行化思路**：LangGraph 的 `Send` 可以把每个子任务作为独立子图运行，适合 I/O 密集型场景。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 子任务互相重叠 | 拆分 prompt 没强调互斥 | 加“每个子任务只覆盖一个独立方面” |
| 子任务粒度不均 | 模型对任务难度判断不准 | 限制子任务数量，或在 prompt 里给示例 |
| 合并后报告逻辑跳跃 | 缺少过渡 | 在 compile 节点让模型写 summary 并润色衔接 |
| 全部串行太慢 | 子任务之间无依赖 | 改用 `Send` 并行执行 |

## 练习建议

1. 把 `topic` 换成你工作中的真实主题（如“对比三款向量数据库”），观察子任务拆分是否合理。
2. 给 `SubTask` 增加 `estimated_length` 字段，让模型预估每节字数。
3. 用 LangGraph `Send` 改写 `worker_node`，实现真正的并行子任务执行。
4. 增加一个人审节点：合并前让用户（或另一个 LLM）审阅大纲，再决定是否继续。
