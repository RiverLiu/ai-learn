# 04 完整 RAG：检索 + 生成

收官章节：把前三章拼成完整的 RAG 问答——对问题检索最相关的知识库块，
塞进提示词让 LLM 基于它回答，并附上出处。

## 本章要点

- 本章代码 = 第 1 章的向量化 + 第 2 章的切块 + 第 3 章的检索（内存版），
  外加唯一的"新"部分 `ask()`：构造提示词并调用 Chat 接口。
- **提示词的两个关键约束**："只根据资料回答，没有就说不知道"（抑制幻觉）、
  "结尾注明来源"（可溯源，方便用户核查）。
- 索引每次启动在内存中重建，方便单文件演示；生产中应像第 3 章那样预构建并持久化，
  或使用真正的向量数据库服务。

## 运行

```bash
uv run tutorials/07_rag/04_rag_pipeline/main.py "专业版多少钱？学生有优惠吗？"
uv run tutorials/07_rag/04_rag_pipeline/main.py "离线编辑冲突了怎么办"
uv run tutorials/07_rag/04_rag_pipeline/main.py "我的笔记会被拿去训练 AI 吗"
```

预期输出：先打印检索到的 Top-3 块及分数，再给出 LLM 基于这些块生成的回答，
结尾附【来源：pricing.md】之类的标注。可以试试知识库里没有的问题（如"支持 Linux 客户端吗"），
观察模型是否如实说不知道。

## 核心概念

- **RAG 的一半是检索，一半是提示词工程**：检索决定 LLM "看得到什么"，提示词决定它 "怎么用"。
- **效果不好时的排查顺序**：先看检索到的块对不对（打印 Top-K 检查），再调块大小/top_k，
  最后才考虑换更强的 Embedding 模型或加重排序（rerank）。大多数"答非所问"是检索没命中，不是模型笨。
- **下一步进阶方向**：混合检索（向量 + 关键词 BM25）、rerank 模型精排、多轮对话改写查询、
  评估集驱动调参。
