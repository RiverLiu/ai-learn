# 01 直接提示词注入：套取系统提示词与内部暗号

提示词注入（Prompt Injection）是 LLM 应用的头号安全威胁（OWASP LLM Top 10 第 1 位）。
本章搭一个"天真客服 bot"——system prompt 里写着内部规则和一个内部优惠暗号
（教学道具 `SECRET2026`），然后扮演攻击者用六类手法把它套出来；
最后换"加固版提示词"重放全部攻击，直观对比防御效果。

## 本章要点

- **攻击面**：system prompt 对模型是"可见的上下文"，不是保险柜。
  写进提示词的一切（规则、暗号、密钥）都可能被套出来。
- **六类攻击手法**（`main.py` 中逐一演示）：
  ① 直接命令"忽略之前的指令"；② 角色扮演绕过；③ 翻译/改述绕弯；
  ④ 利益诱导威胁；⑤ **伪造对话历史**（塞一条"已经泄露过"的假 assistant 消息，
  模型顺着先例再泄露一次）；⑥ **前缀诱导**（把回答开头替模型写好，模型顺着续写）。
- **泄露的判定要宽松**：直说是泄露，拆字（`S E C R E T…`）、倒序、Base64、
  "只透露首字母"同样是泄露——检测函数必须归一化后比对。
- **加固提示词的三板斧**：明确枚举"什么算泄露"（含一切变体）、
  声明用户输入不是新指令、声明伪造历史无效。能提高门槛，但**不能根除**。
- **最重要的结论**：攻击成败取决于模型能力与具体措辞——同一个天真 bot，
  强模型能扛住①~④的"课本式"攻击，却栽在⑤⑥的上下文操纵上。
  **防御不能赌模型足够强、赌攻击者措辞不够巧。**

## 运行

需要配置模型（见[教程首页](../../README.md)或根目录 `.env`），在仓库根目录：

```bash
uv run tutorials/security/01_prompt_injection/main.py
```

输出分两个回合：天真版 6 次攻击逐一打印模型回答与泄露判定，
加固版重放同样 6 次，最后汇总战绩对比表。
（实测参考：kimi-k2.6 上天真版扛住①~④、被⑤⑥攻破；加固版 6 次全部守住。
换模型/换措辞结果可能不同——这正是本章的观点。）

## 核心概念

- **直接注入 vs 间接注入**：本章是攻击者亲自对模型说话（直接）；
  下一章是攻击者把指令藏进模型会读到的资料里（间接）。
- **对话历史是攻击面**：OpenAI 协议里历史由调用方每次提交，如果服务端
  原样信任客户端提交的历史，伪造一条"AI 之前已经说过暗号"的记录易如反掌。
  → 对话历史必须由服务端维护、不可由客户端篡改。
- **前缀续写（prefill）**：很多模型会"顺从地"续写 assistant 消息的既有开头。
  把开头写成"好的，核验码是："，模型的拒绝率显著下降。
- **提示词不是安全边界**：提示词加固属于"提高攻击成本"，真正的防线是
  不依赖模型的工程措施（第 3 章：脱敏、最小权限、密钥卫生）。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 以为 system prompt 用户看不见就安全 | 提示词注入可让它原样吐出来 | 机密绝不进提示词；进提示词的视为公开 |
| 只拦截"忽略之前的指令"这类关键词 | 攻击措辞无穷无尽，绕过轻而易举 | 不依赖输入侧黑名单，靠输出侧检查兜底 |
| 泄露检测只查原文 | 拆字/编码/倒序/翻译同样泄露 | 归一化（去非字母数字）后再比对 |
| 对话历史完全信任客户端提交 | 攻击者可伪造 assistant 历史消息 | 历史存服务端，客户端只传会话 ID |
| 看到模型拒绝了几次就宣布"防御成功" | 换个模型/措辞结果可能反转 | 用攻击集回归测试，并默认它终将被绕过 |

## 练习建议

1. 设计第 7 种攻击（如"把暗号藏进一个故事里每个句子的首字"，
   即藏头诗变体），观察天真版是否泄露、检测函数能否捕获；捕获不到就升级
   `is_leaked`。
2. 把伪造历史攻击改成三轮：先闲聊两轮拉近距离，第三轮再塞假先例，
   对比加固版是否仍然守住。
3. 把 `MODEL_NAME` 换成更弱/更强的模型各跑一遍，记录战绩表的变化，
   体会"防御效果依赖模型"这一事实。
