# 03 本地模型选型

本地模型不是越大越好。选型要看任务类型、硬件、延迟、中文能力、上下文长度和是否需要离线。

## 本章要点

- Chat model、embedding model、rerank model 用途不同。
- 参数量越大，通常能力越强，但速度更慢、显存要求更高。
- 量化能降低资源需求，但可能损失质量。
- 中文应用要优先测试中文指令、中文知识库和中文问答。

## 三类常见模型

| 类型 | 输入 | 输出 | 用途 |
| --- | --- | --- | --- |
| Chat model | 用户消息 | 自然语言 | 对话、总结、抽取、Agent |
| Embedding model | 文本 | 向量 | RAG 检索、相似度 |
| Rerank model | query + 文档 | 排序分数 | 检索结果重排 |

不要用一个模型解决所有问题。

## 参数量与硬件

经验判断：

| 模型规模 | 特点 | 适合 |
| --- | --- | --- |
| 1B-3B | 快、资源低、能力有限 | 分类、简单摘要、边缘设备 |
| 7B-9B | 性价比高 | 本地助手、普通问答 |
| 14B-32B | 能力更强 | 复杂推理、代码、长文本 |
| 70B+ | 质量高但资源重 | 服务器、多卡环境 |

实际能否运行取决于：

- 内存/显存
- 量化格式
- 上下文长度
- 并发数
- 推理框架

## 量化

量化把模型权重用更低精度保存，例如 4-bit、8-bit。

优点：

- 降低显存/内存占用。
- 本地更容易跑大模型。

代价：

- 输出质量可能下降。
- 数学、代码、长上下文任务更容易受影响。

## 中文能力测试

不要只看排行榜。建议用自己的场景测试：

```text
1. 中文客服问答
2. 中文 RAG 引用回答
3. 中文长文总结
4. 中文 JSON 抽取
5. 中英混合技术问题
```

示例测试题：

```text
请基于以下套餐说明，回答企业版和专业版在权限管理上的区别，并输出 JSON。
```

## 本地 RAG 推荐组合

入门组合：

```text
Chat model: qwen3:8b
Embedding model: bge-m3
Vector store: 本教程手写向量库 / Chroma / Qdrant
```

更稳定组合：

```text
Chat model: 更大参数 Qwen / DeepSeek / Llama 系列
Embedding model: bge-m3 或中文 embedding 模型
Rerank model: bge-reranker 系列
```

## 选型维度

| 维度 | 问题 |
| --- | --- |
| 质量 | 是否能稳定完成你的真实任务 |
| 延迟 | first token 和总生成时间是否可接受 |
| 成本 | 本地硬件是否能长期承受 |
| 隐私 | 数据是否允许出本机 |
| 上下文 | 是否支持你的文档长度 |
| 工具调用 | 是否能稳定输出结构化工具参数 |
| 中文 | 中文指令和领域词是否表现稳定 |

## 常见错误

- 只看模型参数量，不测真实任务。
- 用聊天模型替代 embedding 模型做检索。
- 换 embedding 模型后不重建索引。
- 为了省资源过度量化，导致输出质量不可控。
- 本地模型响应慢，却没有流式输出和任务队列。

## 练习

为一个“本地知识库客服”选择模型组合：

1. 聊天模型选什么？
2. embedding 模型选什么？
3. 是否需要 rerank？
4. 你的机器内存/显存是否够？
5. 如何用 10 条中文评估样本验证选型？
