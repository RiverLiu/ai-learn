# Python 开发工具

本目录介绍 Python 开发中常用的环境管理工具。

## 目录

- `01_python_venv.md`：Python 内置虚拟环境 `venv` 基础
- `02_uv.md`：现代 Python 包管理器 `uv` 基础
- `03_uv_demo/`：一个最小的 uv 项目示例
- `04_uvicorn.md`：ASGI Web 服务器 Uvicorn 介绍
- `04_uvicorn_demo/`：纯 ASGI 应用示例
- `05_env_config.md`：`.env`、环境变量、模型配置和密钥安全

## 学习目标

1. 理解为什么需要虚拟环境
2. 掌握 `venv` 的基本用法
3. 掌握 `uv` 的常用命令
4. 能够使用 `uv` 管理项目依赖和运行脚本
5. 理解 Uvicorn 的作用和基本用法
6. 能够用 `.env` 管理本地 AI 应用配置，避免泄露密钥

## 常见面试题

**Q1：为什么 Python 项目需要虚拟环境？**

参考答案：虚拟环境用于隔离不同项目的依赖版本，避免全局 Python 环境被污染。AI 应用常同时依赖 Web 框架、模型 SDK、向量库客户端和评估工具，如果不隔离，版本冲突会很难排查。

**Q2：`uv` 相比传统 `pip + venv` 的优势是什么？**

参考答案：`uv` 集成虚拟环境、依赖解析、安装、运行和 lock 管理，速度快，命令统一。`uv sync` 能复现依赖环境，`uv run` 能在正确环境中运行脚本。

**Q3：为什么 API Key 不应该写在代码里？**

参考答案：密钥写在代码里容易被提交到 git、日志、截图或镜像中。正确做法是用环境变量或 `.env` 管理，只提交 `.env.example`，生产由 Secret 注入。

**Q4：`.env` 和环境变量是什么关系？**

参考答案：`.env` 是本地保存配置的文本文件，程序通过 `python-dotenv` 把它加载为进程环境变量。代码最终应从环境变量读取配置，而不是依赖固定文件路径。

**Q5：`OPENAI_BASE_URL` 为什么通常只写到 `/v1`？**

参考答案：SDK 会自动拼接具体接口路径，例如 `/chat/completions` 或 `/embeddings`。如果手动写到完整接口路径，最终 URL 可能重复，导致 404 或请求错误。

**Q6：lock 文件的价值是什么？**

参考答案：lock 文件记录解析后的精确依赖版本，保证不同机器和不同时间安装到一致环境。对 AI 应用尤其重要，因为模型 SDK、Web 框架和数据处理库版本变化可能影响行为。

**Q7：Uvicorn 在 FastAPI 项目中扮演什么角色？**

参考答案：Uvicorn 是 ASGI 服务器，负责接收 HTTP 连接并把请求交给 FastAPI 应用处理。FastAPI 是框架，Uvicorn 是运行它的服务进程。

**Q8：开发环境和生产环境配置有什么区别？**

参考答案：开发环境常用 `.env` 和本地服务，便于调试；生产环境应使用部署平台 Secret、独立数据库、日志和监控，并避免把密钥写入文件或镜像。

**Q9：为什么示例统一用 `uv run`？**

参考答案：`uv run` 会在项目依赖环境中执行脚本，避免使用系统 Python 或错误虚拟环境。对教程来说，它能降低环境差异带来的运行失败。

**Q10：配置排查时应该先检查哪些项？**

参考答案：先检查 `.env` 是否在正确目录、变量名是否拼错、shell 中是否已有同名环境变量、`OPENAI_BASE_URL` 是否只到 `/v1`、模型名和服务是否匹配。
