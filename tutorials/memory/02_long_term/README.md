# 02 长期记忆闭环：抽取 → 存储 → 注入

短期记忆随会话结束蒸发。长期记忆把"值得记住的"沉淀下来，下次会话继续用。
最小闭环三个环节，本章各对应一个函数：

- **写入（`extract_facts`）**：会话结束时，让 LLM 从对话中筛出值得长期记的事实
  （结构化输出成 `list[str]`）。要点：明确告诉它"闲聊不要"——不加筛选的记忆库
  很快被垃圾淹没。
- **存储（`save_facts`/`load_facts`）**：本章用 JSON 文件合并去重；生产换数据库。
- **读取（`run_session`）**：新会话开场把事实注入 system prompt，
  模型从第一轮起就"认识"用户。

## 运行

需要配置模型。注意 `memories.json` 是运行产物（已 gitignore），删掉即可"失忆"重来：

```bash
uv run tutorials/memory/02_long_term/main.py
```

预期：第一天会话结束后抽出"在减脂""不吃辣""晚上 10 点后才有空"等事实；
第二天全新会话里，助手推荐晚餐时直接避开辣、考虑减脂。

## 核心概念

- **写入时机的取舍**：本章是"会话结束批量抽取"，简单可靠；实时抽取（每轮判断）
  更及时但成本高；还可以给用户"记住这个"的显式指令通道。
- **记忆需要维护**：用户说"我减脂"两个月后又胖了怎么办？本章的 `set` 合并只会
  追加不会纠正——生产系统要给记忆加时间戳、让 LLM 做冲突消解、支持遗忘，这是
  记忆系统的主要复杂度所在（本章点到为止）。
- **全量注入的上限**：几十条事实可以全塞 system prompt；成百上千条时会稀释注意力、
  烧 token——那就该按问题召回了，见第 3 章。
