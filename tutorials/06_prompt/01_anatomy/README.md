# 01 提示词四要素：角色、任务、约束、输出格式

写一个有效的提示词，和写一封好的工作邮件是同一门手艺：告诉对方**你是谁（角色）、
要做什么（任务）、什么不能做（约束）、交回来的东西长什么样（输出格式）**。
缺了任何一项，模型就只能靠猜——而"猜"在工程上叫不可控。

## 本章要点

- **四要素**：
  - 角色（Role）：模型的身份，决定语气和知识边界，如"客服专员小云"；
  - 任务（Task）：具体要做什么，一句话说清，如"回答价格与售后咨询"；
  - 约束（Constraint）：负面清单，如"资料没有的一律说'不清楚'"——这是防幻觉的关键；
  - 输出格式（Format）：答案的结构，如"分点列出、标注来源"——方便人读，也方便程序解析。
- **现场对比**：对虚构产品"云雀笔记"，模糊提问"介绍一下云雀笔记"时模型只能自由发挥——
  要么张冠李戴（把它联想成真实存在的"语雀"），要么凭空编造，回答方向完全不可控；
  四要素提示词 + 事实资料则让模型照章回答，对资料里没有的"学生优惠"老实说"不清楚"。
- **经验法则**：提示词里约束越少，模型自由发挥的空间越大，输出越不可控。

## 核心概念

- **幻觉与自由发挥**：模型没有答案时，不会安静地说"不知道"——它会编造看似合理的内容，
  或把问题往它知道的东西上靠（本章现场："云雀"被联想成"语雀"）。提示词无法让模型
  变聪明，但可以用约束把"不知道"变成一个合法答案。
- **事实资料注入**：模型本身没有你的业务知识，把资料放进提示词（本章做法），
  是最简单的"给模型补课"。资料量大时就演变成 RAG（见 [rag 教程](../../07_rag/)）。
- **system 与 user 的分工**：system 消息定规矩（四要素放这里），user 消息提具体问题。
  规矩每轮都生效，不用每次重复。

## 常见错误

1. **只有任务没有约束**："介绍一下云雀笔记"——模型不知道就会编。
   永远给模型留一条"可以老实说不知道"的退路。
2. **四要素写成了小作文**：要素之间不分段、不标号，模型抓不到重点。
   用清晰的结构（编号、小标题）组织提示词，模型和人一样读结构。
3. **以为格式要求"顺便一提"就行**：输出格式要写明细节（分点？标注？结尾语？），
   否则每次输出的样式都不一样，下游程序无法稳定解析。

## 练习建议

1. 把【事实资料】里专业版价格改成 28 元/月，重新运行，观察好提示词的回答是否跟着变
   （体会"知识来自提示词而非模型"）。
2. 删掉约束里的第 2 条（"一律回答'抱歉，这个我还不清楚'"），再问学生优惠，
   观察模型是否又开始编造。
3. 给好提示词再加一条格式要求："价格用表格输出"，看回答结构的变化。
