# 01 短期记忆三策略

会话内的记忆 = 每轮发给模型的消息列表。它面临一个硬约束：上下文窗口有限、
token 要钱。三种经典策略的取舍：

| 策略 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| 完整历史 | 全部消息都发 | 不丢信息 | token 线性增长，长会话必爆 |
| 滑动窗口 | 只发最近 N 条 | 成本恒定 | 早期信息**必然**遗忘 |
| 摘要压缩 | 旧消息交给 LLM 压成摘要 | 兼顾成本与远期信息 | 摘要是有损压缩；多一次 LLM 调用 |

## 本章要点

- 完整历史**保留在本地**（`self.history`），策略只决定"发给模型多少"——存与取分离。
- 摘要策略的关键是让 LLM 滚动更新摘要：`已有摘要 + 新对话 -> 新摘要`，
  并叮嘱它保留姓名、偏好、约定等关键事实。
- 演示脚本在第 1 轮自报姓名，第 5 轮反问：window 策略必然答不上，full 和 summary 能答上。
- 打印的"本轮发给模型 N 条消息"让你直接看到三种策略的成本差异。

## 运行

需要配置模型（见[教程首页](../README.md#环境准备)）：

```bash
uv run tutorials/11_memory/01_short_term/main.py
```

## 核心概念

- **上下文窗口是预算，不是存储**：短期记忆工程的全部技巧都在"怎么花这个预算"。
- LangChain 生态里对应物：手写窗口/截断可用 `trim_messages`；
  摘要方案有预建的 `SummarizationNode`（langmem 库）。原理都是本章这三板斧。
- 无论哪种策略，会话结束后一切都消失——要"下次见面还认识我"，看下一章。
