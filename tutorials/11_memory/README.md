# Memory（记忆）教程

LLM 本身是无状态的：每次调用都不记得上一次。用户却期望助手"记得我"——
记住我的名字、偏好、上周聊到哪。**记忆系统就是给无状态的模型外挂状态。**

## 记忆的两种时间尺度

| | 短期记忆（Short-term） | 长期记忆（Long-term） |
| --- | --- | --- |
| 范围 | 当前会话内 | 跨会话、跨天、永久 |
| 内容 | 对话历史 | 用户画像、偏好、重要事实 |
| 典型实现 | 消息列表 + 截断/摘要 | 抽取 → 存储 → 注入/召回 |
| 对应框架能力 | LangGraph checkpointer | LangGraph Store / 自建存储 |

记忆与 RAG 的关系：RAG 给模型"知识"（文档），记忆给模型"历史"（与这个用户的过往）。
长期记忆的召回环节（第 3 章）与 RAG 检索技术同构，但记忆是**动态生长**的，
多了"何时写、写什么、如何更新与遗忘"的问题。

## 记忆系统的四个设计问题

1. **写入**：什么时候记？（每轮实时 / 会话结束批量 / 用户明示"记住这个"）
2. **内容**：记什么？（偏好、事实、约定值得记；闲聊不值得）
3. **读取**：怎么用？（全量注入 system prompt / 按当前问题语义召回）
4. **维护**：如何更新冲突信息、如何遗忘？（本教程只点到为止）

## 常见面试题

**Q1：短期记忆和长期记忆有什么区别？**

参考答案：短期记忆服务当前会话，长期记忆跨会话保存用户偏好或事实。

**Q2：为什么不能把所有历史都放进 prompt？**

参考答案：上下文有限、成本高、延迟增加，而且无关历史会干扰回答。

**Q3：滑动窗口记忆是什么？**

参考答案：只保留最近 N 轮对话，简单稳定，但可能丢失较早的重要信息。

**Q4：摘要记忆有什么优缺点？**

参考答案：摘要能压缩上下文，但可能遗漏细节或引入错误，需要评估和更新。

**Q5：语义召回记忆是什么？**

参考答案：把记忆 embedding 后存储，提问时召回与当前任务相关的记忆。

**Q6：长期记忆写入难点是什么？**

参考答案：难在判断何时写入、写什么、如何更新、如何遗忘和如何处理错误记忆。

**Q7：用户偏好适合长期记忆吗？**

参考答案：适合，但应保存来源和更新时间，并允许用户查看和修改。

**Q8：Memory 和 RAG 有什么关系？**

参考答案：二者都可用检索技术；RAG 检索外部知识，Memory 检索用户或会话相关历史。

**Q9：Checkpointer 和 Store 有什么区别？**

参考答案：Checkpointer 保存执行状态，Store 更适合跨会话长期数据。

**Q10：错误记忆有什么风险？**

参考答案：错误记忆会持续影响后续回答，比单次错误更难发现，因此需要置信度、来源和纠错机制。
