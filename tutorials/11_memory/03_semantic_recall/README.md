# 03 语义召回：按问题检索记忆

记忆库积累到几百条后，全量注入既不经济也伤效果（无关信息稀释注意力）。
做法和 RAG 一样：**向量化记忆，按当前问题召回 Top-K 条最相关的注入。**

## 本章要点

- 读取路径变为：`用户问题 -> 向量检索 Top-K 记忆 -> 注入 system -> 生成回答`。
- 打印"召回记忆"可以看到：问晚餐召回的是"减脂/不吃辣/10 点后有空"，
  问代码召回的是"后端工程师/Python/LangGraph"——同一记忆库，各取所需。
- 存储用 `InMemoryVectorStore`（langchain 教程第 4 章同款）；生产换持久化向量库，
  并用 `user_id` 做租户隔离。

## 运行

需要模型 + Embeddings 接口：

```bash
uv run tutorials/11_memory/03_semantic_recall/main.py
```

## 核心概念

- **记忆检索 vs 文档检索（RAG）**：技术同构，差异在数据特性——记忆短、口语化、
  动态生长、带用户边界，且需要配套的写入/更新/遗忘策略（第 2 章）。
  可以理解为"RAG 检索的是世界知识，记忆检索的是'我们之间的历史'"。
- **召回质量是新的瓶颈**：问"猫吃什么"时若召回不到"猫叫年糕"，记忆等于没记。
  调优手段与 RAG 相同：调 k、加元数据过滤（按记忆类型/时间）、混合检索、rerank。
- 至此你已手写完全部机制；下一章看 LangGraph 如何用 Store 把这些做成框架能力。
